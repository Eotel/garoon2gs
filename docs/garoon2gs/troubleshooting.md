# トラブルシューティングガイド

Garoon2GSの使用中に発生する可能性のある問題と解決方法をまとめています。

## 認証関連の問題

### エラー: 401 Unauthorized

#### 症状
```
Error: Failed to fetch events: 401 Unauthorized
```

#### 原因と対処法

1. **ユーザー名/パスワードが間違っている**
   - `.env`ファイルの`GAROON_USERNAME`と`GAROON_PASSWORD`を確認
   - Garoonに直接ログインできるか確認

2. **パスワード認証で使うGaroonログイン情報が不正**
   - Garoon管理者にログイン名とパスワードを確認
   - SAML や 2要素認証の制約がある場合は連携用ユーザーを検討

3. **パスワードに特殊文字が含まれている**
   - パスワードをダブルクォートで囲む: `GAROON_PASSWORD="p@ssw0rd!"`

### エラー: Certificate verification failed

#### 症状
```
Error: x509: certificate signed by unknown authority
```

#### 原因と対処法

1. **自己署名証明書を使用している**
   - システム管理者から正しいCA証明書を入手
   - または環境変数で証明書検証をスキップ（非推奨）

2. **クライアント証明書のフォーマットが正しくない**
   - PKCS#12（.pfx）形式であることを確認
   - 証明書のパスワードが正しいか確認

## Google Sheets関連の問題

### エラー: Permission denied

#### 症状
```
Error: googleapi: Error 403: The caller does not have permission
```

#### 原因と対処法

1. **サービスアカウントに権限がない**
   - スプレッドシートの共有設定を確認
   - サービスアカウントのメールアドレスに編集権限を付与

2. **スプレッドシートIDが間違っている**
   - URLから正しいIDを取得: `https://docs.google.com/spreadsheets/d/{SPREADSHEET_ID}/edit`

3. **Google Sheets APIが無効**
   - Google Cloud Consoleで「Google Sheets API」を有効化

### エラー: Invalid range

#### 症状
```
Error: Invalid range: シート名!A8:Z100
```

#### 原因と対処法

1. **シートが存在しない**
   - `sheet_mapping.csv`の設定を確認
   - スプレッドシートに該当するシートがあるか確認

2. **範囲指定が不正**
   - `HEADER_ROW`と`DATE_COL`の設定を確認
   - シートの実際の構造と一致しているか確認

## データ処理の問題

### 問題: 一部の予定が書き込まれない

#### 症状
- 月の前半の予定が書き込まれない
- 特定のユーザーの予定のみ書き込まれない

#### 原因と対処法

1. **過去日付のスキップ処理**
   - 現在の仕様では実行日より前の日付はスキップされます
   - [開発者向けドキュメント](../development/TODO.md)を参照

2. **ユーザーマッピングの不備**
   - `user_mapping.csv`に該当ユーザーが含まれているか確認
   - ヘッダー名がスプレッドシートと完全一致しているか確認

### 問題: 休暇/外出の判定が正しくない

#### 症状
- 休暇なのに「通常」と表示される
- 外出が認識されない

#### 原因と対処法

1. **イベントメニューの設定ミス**
   ```bash
   # 正しい設定例（JSON配列形式）
   HOLIDAY_MENUS='["休み", "年次休暇", "週休"]'
   
   # 間違った設定例
   HOLIDAY_MENUS="休み,年次休暇,週休"  # カンマ区切りは不可
   ```

2. **Garoonのイベントメニュー名が異なる**
   - Garoonで実際に使用されているメニュー名を確認
   - 環境変数のメニュー配列に追加

## パフォーマンスの問題

### 問題: 処理が非常に遅い

#### 原因と対処法

1. **大量のユーザー/イベント**
   - ユーザー数を制限して実行
   - 期間を短くして実行

2. **ネットワークの問題**
   - プロキシ設定の確認
   - ファイアウォールの設定確認

3. **API レート制限**
   - しばらく待ってから再実行
   - 実行頻度を調整

## 環境設定の問題

### エラー: Cannot find .env file

#### 症状
```
Error: open .env: no such file or directory
```

#### 原因と対処法

1. **`.env`ファイルが存在しない**
   - `.env.sample`をコピーして`.env`を作成
   - 実行ファイルと同じディレクトリに配置

2. **ファイル権限の問題**
   ```bash
   chmod 644 .env
   chmod 644 *.csv
   ```

### エラー: Invalid CSV format

#### 症状
```
Error: Invalid CSV format in user_mapping.csv
```

#### 原因と対処法

1. **CSVフォーマットの問題**
   - 文字コードがUTF-8であることを確認
   - 改行コードがLFまたはCRLFであることを確認
   - ヘッダー行がないことを確認（直接データから開始）

2. **不正な文字**
   - カンマが含まれる場合はダブルクォートで囲む
   - 空白行がないことを確認

## よくある質問

### Q: 実行にどのくらい時間がかかりますか？

A: ユーザー数とイベント数によりますが、目安：
- 10ユーザー × 1ヶ月: 約1分
- 50ユーザー × 3ヶ月: 約5-10分
- 100ユーザー × 3ヶ月: 約15-20分

### Q: 定期実行する方法は？

A: cron（Linux/Mac）やタスクスケジューラ（Windows）を使用：

```bash
# 毎日朝6時に実行（cron例）
0 6 * * * cd /path/to/garoon2gs && ./garoon2gs
```

### Q: 過去のデータを修正できますか？

A: 現在の仕様では、実行日より前の日付は更新されません。手動で修正するか、コードの修正が必要です。

## サポート

問題が解決しない場合は、以下の情報と共に[GitHubのIssue](https://github.com/Eotel/garoon2gs/issues)で報告してください：

1. エラーメッセージの全文
2. 実行環境（OS、Goバージョン）
3. 関連する設定ファイル（機密情報は除く）
4. 再現手順
